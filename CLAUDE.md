## Commands

```bash
composer install                                   # dev dependencies (PHPUnit 12, Testbench 11 / Laravel 13, php-cs-fixer 3, phpmd)
vendor/bin/phpunit -c phpunit.xml.dist             # both suites (live needs the Sandbox)
vendor/bin/phpunit --filter testCfdiUses tests/Model/Catalog/CfdiUseTest.php   # single live test
composer test:live                                 # only the Sandbox catalog tests
composer test                                      # offline suite only (no Sandbox needed)
vendor/bin/phpmd src/ text phpmd.xml.dist          # mess detector (runs in CI)
vendor/bin/php-cs-fixer fix --config=.php-cs-fixer.dist.php --dry-run -v   # style check (src/, tests/, config/, examples/)
```

CI (`.github/workflows/ci.yml`) runs those three checks on PHP 8.3–8.5; 8.3 also runs with `--prefer-lowest`. The package requires `php ^8.3` (Laravel 13's floor). Pushing a `v*` tag runs `.github/workflows/release.yml`, which requires the tag to equal `Client::VERSION`.

## Architecture

This is a thin SDK for the Facturama (Mexican CFDI invoicing) REST API. Everything lives in the `Facturama\` namespace (PSR-4 → `src/`).

- `src/Client.php` is the whole HTTP layer. It exposes only `get/post/put/delete($path, ...)` and returns the decoded JSON (`stdClass`/array/`null`). There are **no per-resource classes**: callers build the arrays themselves and pass API paths such as `catalogs/CfdiUses`. The Guzzle client is injectable (4th constructor arg, mutually exclusive with `$requestOptions`), which is how tests mock HTTP.
- `src/Resource/*` (`Cfdis`, `Clients`, `Products`, reached via `$client->cfdis()` etc.) are thin wrappers that only build the HTTP calls; the endpoint paths mirror `examples/API_Web`.
- `src/Laravel/*` + `config/facturama.php`: optional Laravel integration (`FacturamaServiceProvider` singleton bound to `Client`, `Facturama` facade), auto-discovered via `extra.laravel` in `composer.json`. `illuminate/support` is not a hard dependency, so never import Laravel classes from outside `src/Laravel/`.
- `Client::executeRequest()` translates failures: Guzzle errors become `RequestException` (using the API's `Message`, with `ModelState` messages wrapped in a chained `ModelException`); an unparseable success body raises `ResponseException`. All derive from `Exception\FacturamaException`.
- The default base URL is the **Sandbox** (`https://apisandbox.facturama.mx`); production needs `setApiUrl('https://api.facturama.mx')`.
- `src/Model/Catalog/*` are static offline copies of SAT/Facturama catalogs (`CfdiUse`, `CfdiType`, `PaymentForm`, `PaymentMethod`, `FederalTax`). Each defines `const` entries (`name`, `value`, flags), a `CATALOG_*` list and `findByName()`/`findByValue()` per `CatalogInterface`. When the API adds codes (e.g. CFDI 4.0 `S01`, `CP01`, `CN01`), add the constant **and** append it to the `CATALOG_*` array.
- `examples/` holds runnable scripts by API (`API_Web`, `API_Multiemisor`) and CFDI version. Only CFDI 4.0 examples are kept; 3.3 can no longer be stamped. `examples/Laravel/` shows the Laravel 13 usage.

## Testing notes

- `tests/Model/Catalog/*Test.php` compare the local catalogs against the **live Sandbox API** (with the credentials set in `phpunit.xml.dist`), so they need network access and can fail when the remote catalog changes. `ClientTest`, `ResourcesTest`, `LaravelIntegrationTest` (Orchestra Testbench) and `CatalogsOfflineTest` are offline (Guzzle `MockHandler`/history middleware, local catalogs) and are the `offline` suite (`composer test`). The catalog API tests are the `live` suite because their data providers call the Sandbox at collection time and break any run that includes them without network (use `tests/Support/LiveApiTestCase.php` as their base). PHPUnit 12: use `#[DataProvider]` attributes with `static` providers, not annotations. Note `CfdiType::findByValue()` is a generator (no exception on a miss), unlike the other catalogs.
- `testNoUnusedCfdiUses` and similar tests require the local catalog and the API to match exactly, so removing or renaming an entry can break them.

## Versioning

`Client::VERSION` is the single source of truth; `USER_AGENT` is derived from it. Keep it in sync with `extra.branch-alias` in `composer.json` and `CHANGELOG.md` when releasing.

## Code style

Every PHP file declares `strict_types=1` (enforced by php-cs-fixer, which also applies `@PHP83Migration`): pass real `string`/`int` values, e.g. `getenv()` returns `false` when unset, so use `getenv('X') ?: null`. Catalog constants are typed (`public const array ...`) and `findBy*()` methods carry `#[\Override]`.
